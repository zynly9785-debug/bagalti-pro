# بقالتي برو — ملاحظات النسخة التطويرية

## أضيف في هذه الجولة

- تسجيل متاجر بكلمات مرور مخزنة باستخدام PBKDF2 مع salt عشوائي، وترقية كلمات المرور القديمة إلى التخزين المشتق عند أول دخول ناجح. أزيلت بوابة المالك المحلية ذات السر الثابت من مسار تسجيل الدخول.
- رمز PIN جديد من أربعة أرقام بالضبط عند إنشاء الحساب، وتحقق مماثل عند تغييره.
- بيع يسجل الفاتورة وبنودها وتكلفة الصنف وقت البيع وتغيير المخزون ودين العميل في معاملة SQLite واحدة. يرفض البيع إذا لم يعد المخزون كافياً أو كان المدفوع غير صالح/أعلى من الإجمالي.
- سجل فواتير المتجر مع مشاركة ملخص كل فاتورة عبر Android Sharesheet، ومشاركة فاتورة ما بعد البيع لأي تطبيق مشاركة نصية.
- كشف حساب عميل يعرض الفواتير والرصيد الحالي ودفعات السداد المسجلة، ويمكن مشاركته.
- سجل مستقل لدفعات العملاء مع طريقة الدفع وملاحظة، ورفض السداد الذي يتجاوز رصيد العميل.
- شاشة مصروفات وإجمالي المصروفات ومشاركة القائمة.
- شاشة تقارير تراكميّة تعرض المبيعات والتكلفة التاريخية ومجمل الربح والمصروفات وصافي الربح التقريبي وديون العملاء. التنبيه يوضح أن بيانات التكلفة التاريخية للعمليات القديمة قد تكون غير متاحة.
- إصلاح مسار المرتجعات: يتحقق من المتجر والفاتورة وبنودها والكمية المتبقية، ويحد من قيمة المبلغ، ويحدث المخزون/دين العميل ضمن معاملة.
- إعدادات التجديد تعرض حالة الاشتراك وتاريخه، وتوفر اتصالاً ورسالة/واتساب ومشاركة إلى الرقم `+967778228995`. لا يوجد دفع إلكتروني؛ يحدد مالك التطبيق وسيلة الدفع عند التواصل.
- تهيئة مشاركة النسخ الاحتياطية عبر FileProvider، مع توضيح أن الاستعادة غير مطبقة ولا توهم بإتمامها.
- إزالة مصدر Java قديم غير صالح كان يحوي محتوى Manifest بدلاً من صنف Java. أضيفت روابط سريعة من لوحة المتجر للفواتير والتقارير والمصروفات والمرتجعات.

## ما لم يُنجز بعد

- لوحة مالك التطبيق المركزية وإدارة المستخدمين والاشتراكات عن بُعد تحتاج Backend/API وقاعدة بيانات مشتركة ولوحة إدارة مستقلة؛ ليست موجودة في هذه الحزمة. راجع `OWNER_ADMIN_ARCHITECTURE_AR.md`.
- لم تُنفذ بوابة دفع؛ وسيلة الدفع يحددها المالك بالتواصل.
- الاستعادة من النسخة الاحتياطية، طباعة حرارية، PDF عربي، مزامنة متعددة الأجهزة، تصدير Excel، نطاقات زمنية للتقارير، صلاحيات موظفين، سجل تدقيق شامل، واختبارات آلية تحتاج مراحل لاحقة.
- التقارير الحالية تراكمية وبسيطة. بعض بيانات الفواتير القديمة ستظهر تكلفة تاريخية لها بصفر، لذلك لا يجوز اعتبار الربح التاريخي المحسوب محاسبياً دقيقاً.

## حالة التحقق

فحصت ملفات Java آلياً للتأكد من توازن الأقواس وعدم وجود أسطر خام داخل النصوص، وملفات XML تُفحص قبل التسليم. لم يتم تأكيد Gradle build أو إنشاء APK في بيئة العمل: الأرشيف الأصلي لا يحتوي `gradle-wrapper.jar` ولا يوجد Gradle مثبت أو Android SDK مهيأ في البيئة. يلزم فتح المشروع في Android Studio مع تثبيت SDK وGradle المناسبين ثم إجراء Sync/Build واختبارات تشغيل على جهاز قبل النشر أو إدخال بيانات تشغيلية حقيقية.
